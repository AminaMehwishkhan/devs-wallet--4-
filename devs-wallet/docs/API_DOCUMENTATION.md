# Devs Wallet — API Documentation

This document was generated by reading the actual Express routes, controllers, and validators in `server/`. Every endpoint listed here exists in the code; nothing is aspirational.

## Base URL

| Environment | URL |
|---|---|
| Local development | `http://localhost:5000/api` (or whatever `PORT` is set to in `server/.env`) |
| Production | Depends on where you deployed `server/` (Render, Railway, Vercel, etc.) — set your frontend's `VITE_API_URL` to `<your-backend-url>/api` |

## Response envelope

Every endpoint returns the same shape:

```json
// Success
{ "success": true, "message": "...", "data": { ... } }

// Failure
{ "success": false, "message": "...", "errors": null }

// Validation failure (422)
{ "success": false, "message": "Validation failed", "errors": [{ "field": "email", "message": "Enter a valid email address" }] }
```

## Authentication

Protected endpoints require a JWT in the `Authorization` header:

```
Authorization: Bearer <token>
```

The token is issued by `POST /auth/register` or `POST /auth/login` and encodes `{ id, role }`. On every protected request, the server re-fetches the user from the database (`middleware/auth.js`) — so a suspended account (`status = 'suspended'`) is rejected immediately with `403`, even if the token itself hasn't expired. Admin-only endpoints additionally require `role = 'admin'` (`middleware/role.js`), returning `403` otherwise.

All request bodies are validated server-side with `express-validator` (see `server/validators/`) before reaching any controller — invalid input never touches the database.

## Authentication — `/api/auth`

### `POST /auth/register`
Creates a user and their wallet (balance `0.00`) in one database transaction. No auth required.

**Body:**
```json
{ "fullName": "Amna Khan", "email": "amna@example.com", "phone": "03001234567", "password": "secret123" }
```
`phone` is optional. `password` minimum 6 characters.

**Success (201):**
```json
{
  "success": true,
  "message": "Registration successful",
  "data": {
    "user": { "id": "uuid", "full_name": "Amna Khan", "email": "amna@example.com", "phone": "03001234567", "role": "user", "avatar_url": null, "created_at": "..." },
    "token": "eyJhbGciOi..."
  }
}
```

**Errors:** `422` missing/invalid fields, `409` email already registered.

---

### `POST /auth/login`
No auth required.

**Body:** `{ "email": "amna@example.com", "password": "secret123" }`

**Success (200):** `{ "user": {...}, "token": "..." }` (same user shape as register, minus `created_at`, includes `status`)

**Errors:** `422` missing fields, `401` invalid credentials, `403` account suspended.

---

### `POST /auth/forgot-password`
No auth required. Always returns the same message whether or not the email exists, to avoid leaking which emails are registered.

**Body:** `{ "email": "amna@example.com" }`

**Success (200):**
```json
{ "success": true, "message": "Reset token generated (demo mode: returned directly instead of emailed)", "data": { "resetToken": "..." } }
```
> **Note:** this project has no email provider wired up. The reset token is returned directly in the API response for demo/evaluation purposes instead of being emailed. A production deployment would need Nodemailer/SendGrid/etc. here.

---

### `POST /auth/reset-password`
No auth required.

**Body:** `{ "token": "<resetToken>", "newPassword": "newSecret123" }`

**Success (200):** `{ "message": "Password reset successful. You can now log in." }`

**Errors:** `422` missing/short password, `400` invalid or expired token (tokens expire 30 minutes after being issued).

---

### `GET /auth/me`
**Auth required.** Returns the current user plus their wallet balance/currency.

**Success (200):** `{ "user": {...}, "wallet": { "balance": "0.00", "currency": "PKR" } }`

## Wallet — `/api/wallet`
All endpoints below require auth.

### `GET /wallet`
Returns the caller's full wallet row (`id`, `user_id`, `balance`, `currency`, `created_at`, `updated_at`).

### `POST /wallet/deposit`
**Body:** `{ "amount": 5000, "description": "Salary top-up" }` (`description` optional)
Runs inside a DB transaction. Increments balance, writes a `deposit` transaction row.

**Success (200):** `{ "wallet": {...}, "transaction": {...} }`
**Errors:** `422` amount not a positive number.

### `POST /wallet/withdraw`
Same body shape as deposit. Uses `SELECT ... FOR UPDATE` to lock the wallet row before checking balance, preventing race conditions from concurrent requests.

**Errors:** `422` invalid amount, `400` insufficient balance.

### `POST /wallet/transfer`
**Body:** `{ "recipientEmail": "friend@example.com", "amount": 1000, "description": "..." }`
Recipient must be an existing Devs Wallet user; you cannot transfer to yourself. Writes two linked transaction rows (`transfer_out` on your wallet, `transfer_in` on theirs) atomically.

**Errors:** `422` invalid input, `400` self-transfer or insufficient balance, `404` recipient not found.

## Transactions — `/api/transactions`
All endpoints require auth. Every transaction returned is scoped to the caller's own wallet only.

### `GET /transactions`
Paginated, filterable history.

**Query params (all optional):** `page` (default 1), `limit` (default 10, max 100), `type` (one of `deposit`, `withdraw`, `transfer_in`, `transfer_out`, `bill_payment`, `package_purchase`), `status` (`pending`/`success`/`failed`), `startDate`, `endDate` (ISO dates), `search` (matches against `description`, case-insensitive)

**Success (200):**
```json
{ "transactions": [ {...} ], "pagination": { "total": 42, "page": 1, "limit": 10, "totalPages": 5 } }
```

### `GET /transactions/dashboard-stats`
Powers the Dashboard page. Returns current balance, a 6-month inflow/outflow trend, a spending-type breakdown, and the 5 most recent transactions.

**Success (200):**
```json
{
  "balance": "10000.00",
  "monthly": [{ "month": "Jan", "inflow": "5000", "outflow": "1200" }],
  "breakdown": [{ "type": "deposit", "total": "5000" }],
  "recentTransactions": [ {...} ]
}
```

### `GET /transactions/:id`
Fetches a single transaction by id, only if it belongs to the caller's wallet.

**Errors:** `422` invalid UUID, `404` not found (including if it belongs to someone else).

## Savings Goals — `/api/savings-goals`
All endpoints require auth, all scoped to the caller.

| Method | Endpoint | Body | Notes |
|---|---|---|---|
| GET | `/` | — | List all goals, newest first |
| POST | `/` | `{ title, targetAmount, deadline? }` | `deadline` is an optional ISO date |
| PUT | `/:id` | `{ title?, targetAmount?, deadline?, status? }` | Any field omitted keeps its current value; `status` ∈ `active`/`completed`/`cancelled` |
| DELETE | `/:id` | — | |
| POST | `/:id/contribute` | `{ amount }` | Moves money from the wallet into the goal. Locks the wallet row, checks sufficient balance, and auto-flips the goal to `completed` if `saved_amount` reaches `target_amount`. Also writes a `withdraw`-type transaction row on the wallet describing the contribution. |

**Errors:** `422` validation, `404` goal not found, `400` insufficient balance (on contribute).

## Bill Payments — `/api/bills`
Auth required. Bills are **simulated** — no real utility provider is contacted; a bill payment is a wallet debit + a `bills` record for history.

### `GET /bills`
List the caller's payment history.

### `POST /bills/pay`
**Body:** `{ "category": "electricity", "provider": "LESCO", "accountNumber": "12345", "amount": 500 }`
`category` must be one of `electricity`, `gas`, `internet`, `mobile`.

**Success (200):** `{ "bill": {...}, "wallet": {...} }`
**Errors:** `422` invalid category/missing fields, `400` insufficient balance.

---

## Mobile Packages — `/api/packages`
Auth required. Package purchases are **simulated** in the same way as bills.

| Method | Endpoint | Body | Notes |
|---|---|---|---|
| GET | `/` | — | List the catalog (4 seeded packages: Jazz, Zong, Ufone, Telenor), cheapest first |
| GET | `/my-purchases` | — | Caller's purchase history, joined with package name/network/type |
| POST | `/purchase` | `{ packageId, mobileNumber }` | Debits the wallet by the package price, writes a `package_purchase` transaction + a `package_purchases` row |

**Errors:** `422` invalid input, `404` package not found, `400` insufficient balance.

---

## Beneficiaries — `/api/beneficiaries`
Auth required, scoped to the caller. A beneficiary **must be an existing Devs Wallet user** — added by looking up their email.

| Method | Endpoint | Body |
|---|---|---|
| GET | `/` | — |
| POST | `/` | `{ nickname, beneficiaryEmail, bankOrWallet? }` |
| PUT | `/:id` | `{ nickname?, bankOrWallet? }` — email cannot be changed after creation |
| DELETE | `/:id` | — |

**Errors:** `422` validation, `404` no Devs Wallet user with that email (on add) or beneficiary not found (on update/delete).

## Profile & Security — `/api/profile`
Auth required.

### `PUT /profile`
**Body:** `{ "fullName": "...", "phone": "..." }` (both optional, updates only what's provided)

### `PUT /profile/password`
**Body:** `{ "currentPassword": "...", "newPassword": "..." }`
Verifies the current password with `bcrypt.compare` before hashing and saving the new one.

**Errors:** `401` current password incorrect, `422` new password too short.

### `POST /profile/avatar`
**Content-Type:** `multipart/form-data`, field name `avatar`. Accepts `.png`, `.jpg`, `.jpeg`, `.webp`, max 2MB (`middleware/upload.js`, via `multer`).

**Success (200):** `{ "id": "uuid", "avatar_url": "/uploads/avatars/<filename>" }`

> **Deployment note:** this writes to local disk. It works on a traditional server (Render, a VPS, local dev) but **not** on Vercel's serverless functions, whose filesystem is ephemeral — avatar upload will not persist if the backend is deployed there. See the README's Deployment section.

## Admin — `/api/admin`
**Requires auth + `role: 'admin'`.** A regular user hitting any of these gets `403`.

### `GET /admin/users`
**Query params:** `page`, `limit` (max 100), `search` (matches name or email), `status` (`active`/`suspended`)

**Success (200):** `{ "users": [{ id, full_name, email, phone, role, status, created_at, balance }], "pagination": {...} }`

### `PUT /admin/users/:id/status`
**Body:** `{ "status": "active" | "suspended" }`

### `GET /admin/transactions`
Platform-wide transaction list (joined with the owning user's name/email). Same `type`/`status`/`page`/`limit` query params as the user-facing transactions endpoint.

### `GET /admin/reports`
Aggregate platform statistics.

**Success (200):**
```json
{
  "totals": {
    "total_users": 12, "active_users": 11, "total_wallet_balance": "45000.00",
    "total_transactions": 87, "total_deposits": "60000.00", "total_withdrawals": "10000.00",
    "total_bill_payments": "3000.00", "total_package_sales": "1500.00"
  },
  "monthlyTransactionVolume": [{ "month": "Mar 2026", "transaction_count": "20", "volume": "15000.00" }],
  "newUsersPerMonth": [{ "month": "Mar 2026", "new_users": "4" }]
}
```
(Last 6 months of data for the two arrays.)

## HTTP status code summary

| Status | Meaning |
|---|---|
| 200 / 201 | Success |
| 400 | Business-rule failure (insufficient balance, self-transfer, expired token) |
| 401 | Missing/invalid/expired JWT, or wrong login credentials |
| 403 | Account suspended, or insufficient role for an admin route |
| 404 | Resource not found (or not owned by the caller) |
| 409 | Conflict — duplicate email on register |
| 422 | Request body/query failed validation |
| 500 | Unhandled server error |
